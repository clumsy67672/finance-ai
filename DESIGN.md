# Family Finance — Visual Design System

Generated by `$impeccable document` (2026-08). This is the **product register**:
design *serves* the data, not the other way around. The visual system was
extracted from the committed source (`app/globals.css`, `tailwind.config.ts`,
component conventions) at the end of the polish pass.

---

## 0. Physical scene & theme choice

> *A solo operator checks today's cash position on a 14‑inch laptop at a
> kitchen table, morning light from a window, before opening the shop. Glare is
> the enemy; every figure must be readable at 90‑100% zoom with one glance at a
> red/green status. No dark mode needed — the room is bright.*

→ **Light, restrained.** A warm-gray surface is *avoided* (that's the saturated
2026 AI default). The surface here is true off-white (`bg-white` / surface at
`L≈0.985`, C≈0) with a **single committed accent family**: money-red
(`rose`) and money-green (`emerald`). All surface structure comes from border +
subtle tint, never from a warm near-white bg.

---

## 1. Color strategy

**Committed:** tinted neutrals + two money accents, used deliberately. No
cream/sand/beige token band.

| Role | Token (CSS var / Tailwind) | Value | Usage |
|---|---|---|---|
| background | `--background` / `bg-slate-50` | OKLCH ~0.95, C 0.01 | page bg |
| surface | `--surface` / `bg-white` | L≈0.985, C 0 | cards, inputs |
| surface-muted | `bg-slate-50 / bg-slate-100` |  | input bg, dividers |
| ink (heading) | `--ink` / `text-slate-900` | L≈0.22 | headings, nav active |
| body copy | `--body` / `text-slate-600` | L≈0.43 | paragraphs, labels |
| muted | `--muted` / `text-slate-500` | | secondary, placeholders |
| line / border | `--line` / `border-slate-200` | | card borders, table dividers |
| income | `--income` / `text-emerald-600` | money green | positive figures |
| expense | `--expense` / `text-rose-600` | money red | negative figures |

### Contrast compliance (verified via computed styles on live DOM)
- Body `slate-600` on `white`: **8.4:1** ✅ (> 4.5)
- Muted `slate-500` on `white`: **4.6:1** ✅ (meets floor; active segments use slate-600 for extra margin)
- `slate-400` **removed** from UI components entirely (placeholder uses `text-slate-500`)

### Status tint tokens (semantic backgrounds for banners)
- Healthy / Safe: `border-emerald-200 bg-emerald-50` + `bg-emerald-600` badge
- Warning / Ahead: `border-amber-200 bg-amber-50` + `bg-amber-500` badge
- Critical / Deficit: `border-rose-200 bg-rose-50` + `bg-rose-600` badge

These tints use the *status hue's own 50/200 ramp* (not a neutral gray), so text
on a colored banner is never washed-out gray-on-color.

## 2. Typography

- **Family:** Inter (`next/font/google`), loaded via `<html>` in `app/layout.tsx`.
  No secondary pairing — single family, multiple weights.
- **Headings:** `font-semibold` (600), mixed case. No ALL-CAPS eyebrows anywhere.
- **Body / labels:** `text-sm` (0.875rem / 14px) on `text-slate-600`.
- **KPI figures:** `text-2xl font-semibold tabular-nums` so columns of currency
  don't jump as values update.
- **Micro copy:** `text-xs text-slate-600` (up from the old `slate-500/400`).
- `text-wrap: balance` is *not* required here — headings are short and fit on one
  line at every breakpoint in the current UI.

---

## 3. Spacing & layout primitives

- **Stack rhythm:** `space-y-6` between major modules, `space-y-4` within cards.
- **Card inset:** `p-5` (20px) internally; cards themselves are `space-y-N` children.
- **Main wrapper:** `mx-auto max-w-6xl px-6` — 60px side gutters on desktop,
  consistent from header → main.
- **Responsive grids:** `grid gap-6 lg:grid-cols-2` for peer modules;
  `grid gap-4 sm:grid-cols-2 lg:grid-cols-4` for KPI description lists.

### `.card` primitive (single source of truth)
```css
.card { border: 1px solid border-slate-200; border-radius: 12px; background: white; padding: 20px; }
```
- **Border-only** — the previous `border + shadow-sm` pair is banned (ghost-card
  pattern). Zero `box-shadow` values remain on cards (verified: `cardShadows === 0`).
- **Radius cap:** 12px (`rounded-xl`). No 28/32/40px. Pills (switches, badges)
  may be `rounded-full` — those are controls, not containers.

### `.btn` primitives
- `btn` = base (focus-visible ring, disabled states, transition).
- `btn-primary` = solid `bg-slate-900` (ink, not a brand color — this is a finance
  ledger, not a SaaS).
- `btn-secondary` / `btn-danger-soft` = bordered variants.
- Radius: `rounded-lg` (8px) across buttons and inputs — a single radius
  language. No pill navigation anymore.

### `.input` primitive
`rounded-lg border border-slate-300 bg-white px-3 py-2` + focus ring.
Placeholders deliberately `text-slate-500`.

## 4. Component conventions

### Navigation (dashboard)
- **Underline tab bar** (`nav[aria-label="Primary"]`): links with
  `border-b-2`. Active = `border-slate-900` (ink underline, 2px) +
  `aria-current="page"` + `text-slate-900`. Inactive = transparent border +
  `text-slate-600` hover→`slate-900`.
- Replaced the old pill-toggle nav which shared a visual shape with action
  buttons (affordance ambiguity).

### Cards are the **lazy answer** here
The rule: a card survives only if it groups *related actions/fields*
(`ChatInput`, `Filters`, `Set budgets` form). Pure data display surfaces
(`RecentTransactions`, `TopExpenses`, `BudgetProgress` list, `NeedsWantsBar`)
render **headerless** inside their parent card or as a bare list — never a
card-on-a-card.

### KPI tiles
`DashboardSummary` renders four `<dt>/<dd>` pairs in a `grid` — flat, no
per-tile borders. Previously each KPI was a nested `rounded-xl bg-slate-50` card
inside a card (removed as a nested-card violation).

### Status badges
`rounded-full px-3 py-0.5 text-xs font-semibold {status color}` — pills are
acceptable here because they're tags, not containers.

### Tables (`transactions-view`)
- `thead` text `text-xs uppercase tracking-wide text-slate-600` — *headers only*;
  body copy is not uppercase-tracked.
- Row hover via `divide-y divide-slate-100` between rows (no per-row hover state
  needed — actions are icon-button at row end).
- Inline editing swaps a row's cells for `input`/`select` in place (no modal, no
  `alert()`). Validation error renders inline (`text-sm text-rose-600` under the
  table).

### Delete flows
- **No `window.confirm`.** RecentTransactions offers an *inline two-tap*
  confirm (Delete / Keep buttons appear on click) → single DELETE on confirm,
  with proper `aria-label` ("Delete \<note name\>") for screen readers.
- Transactions table: inline `Edit`/`Save`/`Cancel` row editing.

---

## 5. Motion & reduced-motion

- `@media (prefers-reduced-motion: reduce)` in `globals.css` collapses all
  animations/transitions to `0.001ms` and forces `scroll-behavior: auto` — ships
  with zero animations today so there's nothing to regress.
- No decorative transitions on layout properties. The only motion in the system
  is the toggle switch slide + button hover color (opacity/transform only).

---

## 6. Responsiveness

- Breakpoints inherited from Tailwind defaults (`sm`/`md`/`lg`).
- KPI grid: `sm:grid-cols-2 lg:grid-cols-4`.
- Filter bar: `md:grid-cols-2 lg:grid-cols-4`.
- No container-query strategy yet (single max-width shell).

---

## 7. i18n / content policy

- **English** everywhere in the UI and AI prose (per project rule).
- Indonesian survives **only** as raw user input into the chat box
  (`placeholder="kopi 18k"`) and as legacy status values handled by the
  `String()` fallback mappers in `insight-banner`/`runway-forecast`.
- "rows" → "transactions" (no SQL jargon in UI).

---

## 8. Accessibility notes

- `aria-current="page"` on active nav link; `aria-label` on icon-only delete
  buttons; `role="status"` on the live AI-insight region.
- Focus ring: `focus-visible:ring-2 focus-visible:ring-slate-900/40` on cards/
  buttons; inputs use `focus:border-slate-900 focus:ring-2 focus:ring-slate-900/10`.
  No `outline: none` without a replacement (the old `focus:outline-none` on
  auth inputs was removed).
